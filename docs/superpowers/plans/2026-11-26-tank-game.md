# Tank Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser tank deathmatch for up to 8 friends, joined by invite link, hosted by one player's browser.

**Architecture:** Pure ES modules for simulation, bots, room protocol and client smoothing (all testable in Node). Thin browser modules for PeerJS, canvas, input, sound and screens. The host runs the only authoritative simulation.

**Tech Stack:** Plain JavaScript ES modules, Canvas 2D, PeerJS from CDN (exact pinned version), `node --test`. No build step, no npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-tank-game-design.md`

All paths below are relative to `tank-game/`. Task 1 runs `git init` there.

## Global Constraints

- Up to 8 tanks per room; bots 0 to 7.
- Nothing to run or pay for: static files only.
- No build step, no framework.
- Host simulates at fixed 60 Hz, sends snapshots 30 Hz; clients send only inputs.
- Host clock is a worker timer, never `requestAnimationFrame`.
- Host validates everything from clients. Names never inserted as HTML.
- `sim.js`, `map.js`, `config.js`, `bots.js`, `room.js`, `client.js` use no browser APIs.
- All art drawn in code; all sound synthesized.
- Works in desktop and phone browsers.
- No publishing.

## Review Focus

1. Garbage from a client (NaN aim, `fwd: 1e9`, missing fields, unknown type, second `join`): clamped or ignored, host never throws. (Task 3)
2. Name that is empty, very long or HTML: becomes `Tank` or is cut to 16 characters, shown as text. (Task 3)
3. Window loses focus or a client goes silent while driving: tank stops. (Task 3 host side, Task 5 `blur`)
4. Player leaves with shells in flight: no crash, shells removed. (Task 2)
5. Long stall then one big step: no tank or shell passes through a wall. (Task 1, Task 2)

### Task 1: Map and tank movement

**Files:** Create `package.json` (`{"type":"module","scripts":{"test":"node --test"}}`), `js/config.js`, `js/map.js`, `js/sim.js`, `test/sim.test.js`

**Interfaces — Produces:**

### Task 2: Combat, respawn, power-ups, rounds

**Files:** Modify `js/sim.js`, `test/sim.test.js`

**Interfaces — Produces:**
- `step(state, inputs: {[id]: Input}, dt) -> void`. Missing input = idle. Appends to `state.events` (caller drains with `splice(0)`).
- Events: `{type:'fire'|'bounce'|'brick'|'hit'|'boom'|'pickup', x, y}`; `boom` also has `victim, killer` (names).
- `Shell` = `{id, owner, x, y, vx, vy, life, bounces}`; `Pickup` = `{type, spot, x, y, t}`; types `repair|rapid|triple|shield|speed`.
- `removeTank(state, id) -> void`; `restartRound(state) -> void` (resets scores, bricks, shells, pickups).

Rules: shell does 25, never hurts its owner; steel bounces it once, brick is destroyed with it. Respawn after 3 s at the spawn farthest from living enemies; 2 s invulnerability, ended by firing. `repair` +50 hp capped at 100; `rapid` reload 0.3 for 8 s; `triple` three shells at ±0.15 rad for 8 s; `shield` no damage for 6 s; `speed` ×1.5 for 8 s. Untaken pickup vanishes after 20 s; spot refills 15 s after emptying. Round ends at 15 kills or time 0; `winner` = name with most kills; after 8 s `restartRound` runs.

### Task 3: Bots and room protocol

**Files:** Create `js/bots.js`, `js/room.js`, `test/room.test.js`

**Interfaces — Consumes:** `createState, addTank, removeTank, step, restartRound`.
**Produces:**
- `botInput(state, id) -> Input`: nearest living enemy; aim with small random error; fire when line of sight is clear; drive toward target, turn away and reverse when stuck; wander when no target.
- `sanitizeName(x) -> string` (trim, strip control chars, max 16, fallback `Tank`)
- `sanitizeInput(x) -> Input` (non-finite → 0/false; `fwd`,`turn` clamped)
- `createRoom({hostName, send}) -> Room`, `send(connId, msg)`; host's id is `'host'`.
  - `Room.onMessage(connId, msg)`, `Room.leave(connId)`, `Room.setBots(n)`, `Room.start()`, `Room.setHostInput(input)`, `Room.tick(dt)`, `Room.lobby() -> {players:[{id,name,color,bot}], bots, started}`, `Room.snapshot() -> Snap`, `Room.state`
- Messages client→host: `{t:'join', name}`, `{t:'in', seq, fwd, turn, aim, fire}`. Host→client: `{t:'welcome', id}`, `{t:'full'}`, `{t:'lobby', ...lobby()}`, `Snap`.
- `Snap` = `{t:'snap', time, phase, timeLeft, winner, tanks, shells, pickups, broken: number[], events, acks: {[id]: seq}}`. `broken` = destroyed brick indexes (sent whole, so it self-heals).
- `tick` sends a `Snap` every second tick (30 Hz), draining events. Input older than 1 s is treated as idle. Humans joining a full room replace a bot; with 8 humans, reply `full`.

### Task 4: Client prediction and interpolation

**Files:** Create `js/client.js`, `test/client.test.js`

**Interfaces — Consumes:** `Snap`, `moveTank`.
**Produces:** `createView(myId) -> View`; `View.push(snap, now)`; `View.frame(now, input, dt, seq) -> {tanks, shells, pickups, bricks, phase, timeLeft, winner} | null` (null before first snap). Times in seconds.

Others and shells are drawn 0.1 s in the past, interpolated between snapshots (angles by shortest arc). Own tank: predicted with `moveTank`, position remembered per `seq`; on each snap, `error = server position - remembered position at ack`, fold 20% into the current position; teleport if error > 120 or on respawn.

### Task 5: Rendering, input, sound

**Files:** Create `js/render.js`, `js/input.js`, `js/audio.js`

**Interfaces — Produces:**
- `createRenderer(canvas) -> {draw(view, myId, dt), addEvents(events, myId), screenToAim(px, py) -> radians, reset()}`: camera on own tank, map, tread marks (capped list), tanks with name and health bar, shells, pickups, particles, screen shake, minimap. Handles devicePixelRatio and resize.
- `createInput(canvas, renderer) -> {read() -> Input, destroy()}`: WASD and arrows, mouse aim, click/Space held to fire; on touch devices left stick drives (stick direction → hull turn + throttle), right stick aims and fires. Releases everything on `blur` and `visibilitychange`.
- `createAudio() -> {play(events, listenerX, listenerY), toggleMute() -> boolean}`: WebAudio, volume falls with distance, starts on first user gesture, mute remembered in `localStorage` (inside try/catch).
